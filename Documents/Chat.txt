# 1️⃣ Issue: Too Many Irrelevant Entities Extracted

## Problem with Current Solution (spaCy default NER)

* Extracts generic phrases (“first day”, “last night”)
* Labels normal capitalized words as ORG/PERSON
* Pulls system messages or formatting artifacts
* Treats titles as names (“Master”, “Captain”)
* Splits possessives (Gavle’s → Gavle)

**Why this happens:**
spaCy models are trained on news/Wikipedia, not fictional webnovels with invented terms and stylized writing.

---

## ✅ What We Can Do

### A. Add Post-Extraction Filtering (Very Important)

Filter entities by:

* Minimum frequency (e.g., appears ≥ 3 times)
* Appears across multiple chapters
* Exclude stop-entities (day, night, week, etc.)
* Normalize possessives ('s removal)

Example logic:

```python
if entity_count[name] >= 3 and name not in blacklist:
    keep_entity(name)
```

This alone removes 60–80% noise.

---

### B. Only Keep Certain Entity Types

Limit to:

* PERSON
* ORG
* GPE
* Custom types (RANK, SKILL, CLAN, etc.)

Ignore:

* DATE
* TIME
* CARDINAL
* ORDINAL
* MONEY

---

# 2️⃣ Issue: Fictional Terms Not Recognized

## Problem with Current Solution

spaCy does not recognize:

* Mana Core
* Tier-3 Mage
* Inner Disciple
* Spirit Root
* Upper Realm
* Custom guild names
* Cultivation ranks

It misses the most important worldbuilding elements.

---

## ✅ What We Can Do

### A. Use spaCy EntityRuler (Fast Improvement)

Add pattern rules:

```python
patterns = [
    {"label": "RANK", "pattern": [{"LOWER": {"REGEX": "tier-\d+"}}]},
    {"label": "MAGIC_SYSTEM", "pattern": "mana core"},
    {"label": "FACTION", "pattern": "Inner Disciple"},
]
```

This catches domain-specific phrases immediately.

---

### B. Train Custom NER (Better Long-Term)

Steps:

1. Annotate 200–500 sentences
2. Define custom labels:

   * CHARACTER
   * FACTION
   * LOCATION
   * CULTIVATION_LEVEL
   * SKILL
   * ARTIFACT
3. Fine-tune spaCy or a HuggingFace BERT model

Result:
Much higher precision on fictional text.

---

### C. Use Fiction-Oriented Tools

Look into:

* BookNLP (character extraction + coreference)
* HuggingFace NER models fine-tuned on literary text
* Transformer-based NER (RoBERTa/BERT)

These handle story text better than default spaCy.

# 3️⃣ Issue: Duplicate and Variant Names

## Problem with Current Solution

The system creates multiple wiki pages for:

* Gavle
* Gavle’s
* Lord Gavle
* Gavle Stormborn
* He (coreference issue)

You end up with fragmented entities.

---

## ✅ What We Can Do

### A. Normalize Names

Remove:

* ’s
* Titles (Lord, Master, Elder)
* Extra whitespace

Example:

```python
name = re.sub(r"(’s|'s)$", "", name)
```

---

### B. Use Coreference Resolution

Tools like:

* NeuralCoref
* BookNLP

This merges:

* “Gavle”
* “He”
* “The Guild Master”

Into one canonical entity.

---

### C. Frequency + Similarity Clustering

Use:

* Fuzzy matching
* Levenshtein distance
* Sentence embeddings

To merge similar names automatically.

# 4️⃣ Issue: Important Entities Ranked the Same as Minor Ones

## Problem

A character mentioned once gets a full wiki entry like the protagonist.

---

## ✅ What We Can Do

### A. Frequency-Based Ranking

Score entities using:

* Total mentions
* Chapter spread
* Dialogue presence
* Network centrality

Only auto-create wiki pages for high-score entities.

---

### B. Build a Co-occurrence Graph

Using NetworkX:

* Nodes = entities
* Edges = appear in same paragraph/chapter
* Rank by centrality

Main characters naturally rise to top.

---

# 5️⃣ Issue: Pure NER Is Not Enough for a Wiki

## Problem

NER extracts names — but not:

* Relationships
* Powers
* Affiliations
* Descriptions

---

## ✅ What We Can Do

### A. Hybrid Pipeline (Recommended Architecture)

Instead of:

```
NER → Wiki
```

Use:

```
Chapters
   ↓
NER + EntityRuler
   ↓
Normalization
   ↓
Frequency Filter
   ↓
Coreference Resolution
   ↓
Relationship Extraction
   ↓
Graph Ranking
   ↓
Wiki Generation
```

---

### B. Optional: LLM Refinement Layer

Send extracted entity chunks to an LLM:

Prompt:

> “Summarize who Gavle is based only on this text.”

This produces clean wiki entries automatically.
